# Архітектура живої анімації поверх скріншоту воркфлоу n8n

Цей документ описує технічний підхід, за яким реалізовано живий інтерактивний оверлей поверх реального production-скріншоту n8n (на прикладі кейсу **«Дебет-контроль»**).

Ідея полягає в тому, щоб **не перемальовувати редактор n8n з нуля**, а зберегти автентичний вигляд воркфлоу (реальні іконки, сітку, шрифти, підписи) і накласти зверху **синхронізований 1:1 векторний SVG-шар**, яким керує єдиний **GSAP Master Timeline**.

---

## 1. Принцип 1:1 координатного накладання (Coordinate Lock)

Головна вимога — на будь-якій ширині екрана (від мобільного до 4K) підсвічені дроти, рамки вузлів і бейджі `✓` не повинні зміщуватися навіть на один піксель.

- Визначається нативна роздільна здатність PNG-скріншоту (для «Дебет-контролю» — `1191 × 547 px`).
- Сцені задається жорстке співвідношення сторін `aspect-[1191/547]`.
- Нижнім шаром рендериться оригінальний скріншот (`w-full h-full object-fill`), а поверх нього через `position: absolute; inset: 0` кладеться `<svg viewBox="0 0 1191 547">`.

```tsx
<div className="relative w-full aspect-[1191/547] select-none overflow-hidden">
  <Image
    src={screenshotSrc}
    width={1191}
    height={547}
    alt="Production n8n workflow screenshot"
    className="w-full h-full object-fill block pointer-events-none"
  />
  <svg
    viewBox="0 0 1191 547"
    className="absolute inset-0 w-full h-full"
  >
    {/* Шари 2–4 */}
  </svg>
</div>
```

Оскільки зображення й SVG ділять однаковий `aspect-ratio` та систему координат `0..1191 × 0..547`, браузер масштабує їх абсолютно синхронно.

## 2. Піксельне калібрування вузлів і дротів

Координати кожного елемента знімаються безпосередньо з піксельного буфера PNG-зображення і фіксуються у типізованій специфікації `ScreenshotOverlaySpec` (`lib/n8nScreenshotOverlay.ts`).

### Координати вузла (`ScreenshotNodeBox`)
Для кожного вузла зберігаються два прямокутники:
- **Візуальний квадрат** (`x, y, w, h, rx`) — точно по контуру білої картки вузла для рамки виконання й пульсації.
- **Інтерактивна зона** (`hitX, hitY, hitW, hitH`) — трохи ширша область, що охоплює і сам квадрат, і текстову назву під ним для зручного кліку та наведення.

```ts
export interface ScreenshotNodeBox {
  nodeId: string;
  x: number;
  y: number;
  w: number;
  h: number;
  rx: number;
  hitX: number;
  hitY: number;
  hitW: number;
  hitH: number;
  isTrigger?: boolean;
  isAi?: boolean;
  isLoop?: boolean;
  isIf?: boolean;
}
```

### Траєкторії дротів (`ScreenshotWirePath`)
Кожен сірий дріт на скріншоті дублюється точною SVG-кривою `d`:
- **Прямі сегменти** (`M x1 y1 L x2 y2`) — між сусідніми вузлами в рядку.
- **Кубічні криві Безьє** (`M ... C ...`) — для плавних переходів від тригерів і на розгалуженнях `IF`.
- **Ортогональні рейки із заокругленнями** (`M ... L ... Q ...`) — для довгого переходу з верхнього ряду в нижній та зворотної петлі циклу `SplitInBatches`.

```ts
export interface ScreenshotWirePath {
  id: string;
  fromNodeId: string;
  toNodeId: string;
  kind:
    | 'trigger'
    | 'main'
    | 'return-rail'
    | 'loop-out'
    | 'loop-back'
    | 'done-out'
    | 'branch-true'
    | 'branch-false';
  d: string;
}
```

## 3. Чотиришарова структура сцени

Елементи накладаються один на одного знизу вгору:

1. **Шар 1 — Автентичний скріншот (`<Image>`)**  
   Базовий візуальний фон без перемальовування редактора.
2. **Шар 2 — Кольорові дроти виконання (`<path>`)**  
   Лежать точно поверх сірих ліній n8n і початково сховані (`opacity: 0`). Колір має чітку семантику:
   - `#CC4518` (теракотовий) — основний потік та гілка `IF = true` (аномалія → OpenAI);
   - `#4338CA` (індиго) — петля пакетної обробки `SplitInBatches` (`loop-out`, `loop-back`);
   - `#0F766E` (смарагдовий) — вихід `done` та економна гілка `IF = false` (`$0 LLM`).
3. **Шар 3 — Стани вузлів і рухомий пакет даних**
   - `activeRing` — зовнішня пульсуюча рамка, коли вузол виконується в поточну мить;
   - `doneBorder` + `doneBadge` — смарагдова рамка й круглий бейдж `✓` у правому нижньому куті квадрата (відтворює рідний стан виконаного вузла в n8n);
   - `packetGroup` — світлова точка (ядро + напівпрозоре гало з SVG-фільтром `<feGaussianBlur>`), що фізично рухається по кривій;
   - контекстні індикатори: бейдж ітерації `×1/2`, `×2/2` над `SplitInBatches`, а в режимі «Норма ($0 LLM)» — напівпрозора вуаль поверх пропущених вузлів OpenAI.
4. **Шар 4 — Інтерактивні Hit Targets**  
   Прозорі `<g role="button" tabIndex={0}>` для всіх вузлів. Обробляють hover, click та клавіатурну навігацію (`Enter` / `Space`), синхронізуючи вибраний вузол із панеллю технічних нотаток.

## 4. Декларативний план виконання (відокремлений від UI)

Послідовність виконання описується чистою функцією `buildScreenshotExecutionPlan(branch)` у `lib/n8nScreenshotOverlay.ts`, без жодних залежностей від React чи DOM:

- Сценарій **`anomaly`** (`IF = true`): 17 кроків — включно з 2 ітераціями циклу `SplitInBatches`, викликом OpenAI та злиттям висновку у звіт.
- Сценарій **`normal`** (`IF = false`): 15 кроків — після `IF` потік іде прямо в Telegram, а вузли `dc-openai-guard` і `dc-merge-ai` потрапляють у `skippedNodeIds`.

Кожен крок (`ExecutionStep`) містить:
- `wireId` — яким дротом надходять дані;
- `nodeId` — який вузол активується;
- `loopIteration` (`1 | 2`, опційно) — для відображення лічильника циклу;
- `wireDurationSec` та `nodeDwellSec` — індивідуальні таймінги (довші на поворотних рейках і ключових вузлах `IF` / `OpenAI`);
- `captionUk` / `captionEn` — локалізований технічний коментар кроку.

Оскільки функція чиста, її легко покривати unit-тестами (`lib/n8nScreenshotOverlay.test.ts`), перевіряючи повноту маршрутів, цикли та пропущені гілки.

## 5. Механіка GSAP Master Timeline

У компоненті `components/LiveN8nScreenshotOverlay.tsx` при монтажі або зміні гілки `branch` у `gsap.context()` збирається єдиний зациклений таймлайн:

```ts
const tl = gsap.timeline({
  repeat: -1,
  repeatDelay: 1.8,
  onRepeat: () => resetVisualState(),
});
```

Для кожного кроку плану виконуються три синхронні техніки:

### 5.1. «Промальовування» дроту через `stroke-dashoffset`
1. Перед побудовою таймлайну вимірюється точна довжина кожного SVG-шляху: `const len = pathEl.getTotalLength()`.
2. Встановлюються `strokeDasharray: len` і `strokeDashoffset: len` (лінія повністю схована).
3. GSAP анімує `strokeDashoffset: len → 0` з `ease: 'power1.inOut'`, створюючи ефект заповнення дроту по ходу руху даних.

### 5.2. Рух світлового пакету строго по кривій (`getPointAtLength`)
Паралельно з промальовуванням дроту (позиція `'<'` у таймлайні) анімується проксі-об’єкт `{ p: 0 } → { p: 1 }`:

```ts
tl.to(
  proxy,
  {
    p: 1,
    duration: step.wireDurationSec,
    ease: 'power1.inOut',
    onUpdate: () => {
      const pt = pathEl.getPointAtLength(proxy.p * len);
      packetGroupRef.current?.setAttribute(
        'transform',
        `translate(${pt.x.toFixed(1)}, ${pt.y.toFixed(1)})`
      );
    },
  },
  '<'
);
```

Нативний метод SVG `getPointAtLength` повертає точні координати `(x, y)` у будь-якій точці кривої Безьє чи заокругленого кута, тому пакет ідеально тримається траєкторії на всіх поворотах.

### 5.3. Активація й завершення вузла
Щойно пакет долітає до цільового вузла:
1. `tl.call(...)` оновлює номер кроку (`07/17`), бейдж ітерації циклу та активний підпис в інспекторі.
2. Спалахує та плавно затухає зовнішня рамка `activeRing`.
3. З легким перекриттям (`-=0.14`) проявляється смарагдова рамка `doneBorder`, і вискакує бейдж `✓` із пружинним `ease: 'back.out(2)'`.

## 6. Продуктивність, керування та доступність

- **Без зайвих ре-рендерів React на 60 fps**: усі покадрові зміни (`strokeDashoffset`, `transform`, `opacity`, `scale`) GSAP застосовує напряму через DOM-рефи (`useRef`). Стан React оновлюється лише на межі кроків (~2 рази на секунду).
- **Миттєвий контроль відтворення**:
  - `Пауза / Старт` → `tl.pause()` / `tl.play()`;
  - `Повторити` → `tl.restart(true)`;
  - Перемикач гілки (`Аномалія → OpenAI` / `Норма → $0 LLM`) перебудовує план і таймлайн під обрану гілку `IF`.
- **Підтримка `prefers-reduced-motion`**: якщо користувач вимкнув анімації в налаштуваннях ОС, GSAP-таймлайн не запускається — натомість одразу відмальовується фінальний статичний стан пройденого маршруту з активними дротами та зеленими галочками.

## 7. Чекліст для підключення нового воркфлоу

Щоб «оживити» будь-який наступний скріншот n8n за цією ж схемою:

1. Додати PNG-скріншот воркфлоу в `public/assets/...` і зафіксувати його нативні `width × height`.
2. Зняти координати квадратів вузлів (`nodes`) та SVG-шляхи з’єднань (`wires`) у конфіг `ScreenshotOverlaySpec`.
3. Описати послідовність кроків `ExecutionStep[]` (включно з циклами або гілками `IF`, якщо вони є).
4. Прив’язати `nodeId` до метаданих вузлів (назва, тип, інженерні нотатки) для клікабельного інспектора.
5. Перевірити у браузері вирівнювання рамок/ліній на десктопі й мобільному та додати unit-тест на план виконання.
